# DW Professional Portfolio — v1.0.1

## Summary

This maintenance release formalises the repository's deployment and release process, publishes the portfolio's reusable design tokens as a GitHub Package, and retires two obsolete GitHub deployment environments.

## Highlights

- Adds a release-driven GitHub Actions publishing workflow with least-privilege permissions.
- Introduces `@domwokorach/dw-professional-design-tokens` as a focused reusable CSS package.
- Aligns the application, package, Git tag and release at version `1.0.1`.
- Documents package installation, release policy and ownership boundaries.

## Features

- Consumers can import the canonical DOMINIC Portfolio light and dark CSS variables from a versioned package.
- The package is generated directly from `src/styles/base.css`, preventing a second source of truth.

## Fixes

- Corrects the root package metadata so its licence points to the repository's proprietary `LICENSE.md` instead of identifying the project as ISC-licensed.
- Removes the obsolete `Production – dw-test-developer` and `Production – dw-professional` GitHub deployment histories and environment records.

## Technical changes

- Adds an npm workspace for reusable packages.
- Adds automated version alignment checks, type checking, tests, application build and package build before publication.
- Uses the release workflow's short-lived `GITHUB_TOKEN` with `contents: read` and `packages: write`; no publishing secret is stored in the repository.

## Documentation changes

- Adds package installation and release/versioning guidance to the root README.
- Adds package-specific usage and licensing documentation.

## Deployment notes

- The production branch remains `master`.
- The canonical Vercel project remains `dw-professional`; the production domain and database configuration are unchanged.
- Publishing this GitHub release triggers the package workflow.

## Known issues

- GitHub Packages npm installs require GitHub Packages authentication, including for public source repositories.
- The application has no separate ESLint command; its existing Next.js production build performs the configured framework validation, alongside the explicit TypeScript check and test suite.
